# What EV is expected to do

Generated by `npm run verify -- --accept` from `verify/checks/`. Do not edit by hand: change the check, then accept.

Each line is one behaviour a person would notice. ✓ holds today, ✗ does not yet, · has no automatic check.

## What already works and must keep working

EV already tells talk from work, runs an agent, reviews the result until it is right, asks when only the person can answer, and stops when told. None of that may break while the insides are rebuilt.

- ✓ **K-01** Small talk gets an answer and starts no work.
- ✓ **K-02** A request becomes one task, and its result and file reach the conversation.
- ✓ **K-03** Work the reviewer sends back returns to the same agent with the feedback, and the person hears only about the accepted version.
- ✓ **K-04** A question only the person can answer reaches them, and their answer continues the same work.
- ✓ **K-05** "Stop" stops running work, and nothing is delivered for it.
- ✓ **K-06** When the model cannot be reached, nothing starts, EV says so once, and the message is not lost.
- ✓ **K-07** Something the person states about themselves is known to EV on their next message.
- ✓ **K-08** After "forget that", the memory is gone from what EV knows and from the memory page.
- ✓ **K-09** A page on another website cannot talk to EV.

## Task 3: One store with real ids

Everything EV holds lives in one place and is linked: a message to the work it started, the work to its result, a memory to where it came from. Because of that, forgetting reaches every copy, a restart loses nothing, and a result can never be too large to keep.

- ✗ **S-01** After "forget that", the forgotten text is in no file EV keeps and no page it serves.
- ✓ **S-02** A restart in the middle of a review loop keeps the loop: the reviewer still knows which round it is and what it asked for.
- ✓ **S-03** Tokens spent before a restart still count, so the budget is a real limit.
- ✗ **S-04** A long review loop with detailed feedback still ends in a delivered result; accepted work is never lost for being large.
- ✗ **S-05** EV's "done" message is tied to the work it is about, so the page can show the result under it.
- ✗ **S-06** Each task's agent has its own home: one task cannot read what another task's agent left behind.

Judged with a real model (`npm run qa`, scenario ids in `qa/scenarios/`):

- `L8-01` After "forget that", EV cannot bring the detail back in any later conversation, however it is asked.

## Task 4: One conversation, one thing at a time

A conversation is a queue. Whatever happens in it (a message from the person, work finishing, an agent asking something) is saved the moment it happens and handled in order, so EV always decides with the full picture and the person never has to say something twice or wonder whether it arrived.

- ✗ **Q-01** A message is saved the moment it arrives, before EV has decided anything about it.
- ✓ **Q-02** Two messages sent in quick succession are handled in order: the second is read knowing the first and what it started.
- ✗ **Q-03** A message EV has received survives a crash and is answered afterwards without being sent again.
- ✓ **Q-04** A change sent while the result is being reviewed reaches the agent before the work can be called done.
- ✓ **Q-05** Work that finishes after a restart is announced exactly once.
- ✗ **Q-06** Opening a long conversation lands on the newest message, not the oldest.
- ✗ **Q-07** The page shows the message at once and that EV is thinking, for as long as it is.

Judged with a real model (`npm run qa`, scenario ids in `qa/scenarios/`):

- `L6-01` A correction sent right after a request changes that request; it does not start a second, unrelated task.

## Task 5: EV1 can look things up and act through tools

EV1 is a coordinator with a small set of tools: it can search and read everything EV holds, reply, ask, start work and talk to running work. It cannot execute anything itself. Nothing decides in advance what it may see, so it can answer from a conversation three weeks old as easily as from the last message, and it always knows what its own actions actually did.

- ✗ **T-01** EV1 can find something the person said long ago in the same conversation.
- ✗ **T-02** EV1 can find something said in a different conversation.
- ✗ **T-03** EV1 can read the whole of a finished result, not only its first lines.
- ✗ **T-04** Asked how running work is going, EV1 can see where it really stands, and asking starts nothing new.
- ✗ **T-05** EV1 is offered tools to search, read and coordinate, and none that would let it execute anything itself.
- ✗ **T-06** One message with two unrelated asks becomes two pieces of work, each with its own result.
- ✗ **T-07** What the person asked EV to forget cannot be found by searching either.
- ✗ **T-08** Text written by an agent or a web page reaches EV1 only as the result of a lookup, never mixed into what it is told to do.
- ✗ **T-09** EV1 learns what its action actually did, so it never tells the person something happened when it did not.
- ✗ **T-10** When EV asks a question, it also says what it will assume if the person does not answer.

Judged with a real model (`npm run qa`, scenario ids in `qa/scenarios/`):

- `L6-02` "How is that going?" gets real progress from the running work and starts nothing new.
- `L8-02` "Use the layout I described for the other report" is resolved from an earlier conversation without asking.
- `L8-03` A message with two unrelated asks produces two results.
- `L8-04` A vague request comes back with a stated assumption instead of a question when being wrong is cheap.

## Task 6: Sessions from outside EV

Work the person did elsewhere (Claude Code on this machine first, then web and cloud sessions) is brought into the same store, so EV can draw on every conversation they have had, not only the ones that happened in EV. Imported text is something EV can look up; it is never an instruction and never silently becomes a fact about the person.

- ✗ **I-01** A Claude Code session can be imported, after which EV1 finds what was said in it and can tell which project it came from.
- ✗ **I-02** Importing the same session twice adds nothing the second time.
- ✗ **I-03** When a session has grown since it was imported, importing again adds only the new part.

## Task 7: Work that can be picked up again, watched and really checked

Most of what people say after a result is a follow-up, so finished work can be continued where it stands. A run is watched for progress, not for the time on a clock, and a run that dies is resumed instead of failing the task. The reviewer opens and tries the real output before the person ever sees it, and can reach nothing outside the task it is reviewing.

- ✗ **R-01** A follow-up on finished work continues that same work, with its files, instead of starting over as a new task.
- ✓ **R-02** An agent that keeps making progress is left to finish, however long it takes.
- ✗ **R-03** An agent that goes silent is noticed within the stall limit, and its task is resumed, not failed.
- ✗ **R-04** After EV crashes, the agent it left behind is stopped before a new one takes over the same work.
- ✗ **R-05** The reviewer can see all of the delivered file, not just what the agent says about it.
- ✓ **R-06** The reviewer is never shown a file outside the task it is reviewing, even when the agent's report points at one.

Judged with a real model (`npm run qa`, scenario ids in `qa/scenarios/`):

- `L6-04` "Make it shorter" after a delivered document changes that document; there is still one task and one file.

## Task 8: Memory that deepens over time

EV knows the person the way a long-time colleague does. It keeps a short dated history of what happened and can open any line of it back to the original words. It saves what matters as it hears it. It can tell what the person said from what it guessed, and a guess becomes knowledge only when it holds up across separate occasions. Nothing it once knew is lost when it changes, and nothing it was asked to forget survives anywhere.

- ✗ **M-01** EV1 is told today's date, so "since when" and "how long ago" can be answered.
- ✗ **M-02** EV1 can save something the person just said, and it is in memory before the reply is sent.
- ✗ **M-03** EV1 cannot save a guess as something the person said: without their own words behind it, a memory stays tentative.
- ✗ **M-04** A guess becomes established only after it shows up on separate occasions, not twice in one conversation.
- ✗ **M-05** When something about the person changes, what EV knew before can still be found, marked as no longer current.
- ✗ **M-06** EV keeps a dated history of what happened that stays short however much happens, and every line opens back to its source.
- ✗ **M-07** Forgetting something removes it from the history as well.

Judged with a real model (`npm run qa`, scenario ids in `qa/scenarios/`):

- `L8-05` Asked what they were working on two weeks ago, EV answers from its history with rough dates.
- `L8-06` A preference shown by behaviour but never stated is treated as a hint; EV says so or checks once.
- `L8-07` After a correction, EV can still say what was true before and when that changed.
- The twelve-week arc (`npm run qa:arc`) is the real measure here: understanding should rise week over week instead of drifting.
